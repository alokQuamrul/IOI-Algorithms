SECTION 01

Stack & Queue — Quick Recap

Before diving into the implementation, let's lock in the two data structures involved.

⬆ STACK — LIFO
  • Last In, First Out
  • push(x) — add to top
  • pop() — remove from top
  • top() — peek at top
  • Think: stack of game save states
➡ QUEUE — FIFO
  • First In, First Out
  • enqueue(x) — add to back
  • dequeue() — remove from front
  • front() — peek at front
  • Think: player matchmaking queue

SECTION 02

Core Concept — Stack Using Queue

A queue follows FIFO. A stack follows LIFO. They're opposites. The trick is to do extra work during either push or pop to flip the order. There are two classic strategies:

STRATEGY A — Make Push Costly

Keep a second auxiliary queue. Every time you push a new element:

  1. Enqueue the new element into the empty q2.
  2. Dequeue everything from q1 and enqueue it into q2 (the new element is now at the front).
  3. Swap the names of q1 and q2. Now q1 always holds elements in LIFO order.

Pop is O(1) — just dequeue from the front of q1.

STRATEGY B — Make Pop Costly

Just enqueue on push. The work happens on pop/top:

  1. Move all-but-the-last element from q1 into q2.
  2. The single remaining element in q1 is your stack top.
  3. Swap q1 and q2.

Push is O(1). Pop and Top are O(n).

⚡ PERFORMANCE NOTE
Both approaches give the same overall amortized throughput for general use. In game development, Strategy A (Push-Heavy) is preferred when you pop or peek more often than you push — which is common in undo systems and state machines.

Python Implementation — Both Methods

We use Python's collections.deque as our queue primitive. Both methods are shown side-by-side — toggle between them using the tabs below, then compare their behaviour in the shared trace table.

METHOD 1
Push-Heavy
push O(n) pop O(1) top O(1)

Rearranges on every push so the newest element is always at the front of q1. Best when you read/pop more than you push — e.g. undo systems.

VS
METHOD 2
Pop-Heavy
push O(1) pop O(n) top O(n)

Simply appends on push. Work is deferred to pop/top. Best when you write/push far more than you read — e.g. event logging.

Python — Method 1: Push O(n) | Pop O(1) | Top O(1) 
# ═══════════════════════════════════════════════════════
# Stack Using Two Queues — METHOD 1 (Push-Heavy)
# Push: O(n)  |  Pop: O(1)  |  Top: O(1)
# ═══════════════════════════════════════════════════════

from collections import deque

class Stack:
    def __init__(self):
        # q1 = main queue (always holds elements in LIFO order)
        # q2 = temporary auxiliary queue
        self.q1 = deque()
        self.q2 = deque()

    def push(self, x):           # O(n)
        # Step 1: Enqueue new element into empty q2
        self.q2.append(x)

        # Step 2: Move ALL of q1 into q2
        #   ➜ new element is now at the FRONT of q2
        while self.q1:
            self.q2.append(self.q1.popleft())

        # Step 3: Swap names — q1 now has correct LIFO order
        self.q1, self.q2 = self.q2, self.q1

    def pop(self):                # O(1)
        # Front of q1 is always the stack top — just dequeue it
        if self.q1:
            self.q1.popleft()

    def top(self):                # O(1)
        # Peek at front without removing
        if self.q1:
            return self.q1[0]
        return None

    def size(self):               # O(1)
        return len(self.q1)

    def is_empty(self):          # O(1)
        return len(self.q1) == 0

Python — Method 2: Push O(1) | Pop O(n) | Top O(n) 
# ═══════════════════════════════════════════════════════
# Stack Using Two Queues — METHOD 2 (Pop-Heavy)
# Push: O(1)  |  Pop: O(n)  |  Top: O(n)
# ═══════════════════════════════════════════════════════

from collections import deque

class Stack:
    def __init__(self):
        self.q1 = deque()   # primary queue
        self.q2 = deque()   # auxiliary queue

    def push(self, x):           # O(1) — no rearranging needed
        self.q1.append(x)

    def pop(self):                # O(n)
        if not self.q1:
            return

        # Step 1: Drain all but the last element into q2
        while len(self.q1) != 1:
            self.q2.append(self.q1.popleft())

        # Step 2: The lone element remaining is the stack top — discard it
        self.q1.popleft()

        # Step 3: Swap — q2 is now the new q1
        self.q1, self.q2 = self.q2, self.q1

    def top(self):                # O(n)
        if not self.q1:
            return None

        # Step 1: Drain all but last element into q2
        while len(self.q1) != 1:
            self.q2.append(self.q1.popleft())

        # Step 2: Read (but keep!) the last element
        top = self.q1[0]
        self.q2.append(self.q1.popleft())  # move it to q2 too

        # Step 3: Swap back — all elements restored to q1
        self.q1, self.q2 = self.q2, self.q1

        return top

    def size(self):               # O(1)
        return len(self.q1)

    def is_empty(self):          # O(1)
        return len(self.q1) == 0

    s.push(1)
    s.push(2)
    s.push(3)

💡 ONE-QUEUE BONUS TRICK
You can implement a stack using just one queue! After enqueueing a new element, rotate the queue (dequeue and re-enqueue) size−1 times so the newest element reaches the front. This is slightly more cache-friendly on certain architectures.
SECTION 04

Python — Bonus: Single Queue Method

Both methods above used two queues. Here's a leaner variant with just one queue: after every push, rotate the queue so the newest element arrives at the front. Same O(n) push cost as Method 1, but uses half the memory for the auxiliary structure.

Python — Bonus: Single Queue Method 
# Stack Using a SINGLE Queue

from collections import deque

class Stack:
    def __init__(self):
        self.q = deque()

    def push(self, x):
        self.q.append(x)
        # Rotate the queue so new element is at front
        for _ in range(len(self.q) - 1):
            self.q.append(self.q.popleft())

    def pop(self):
        if self.q:
            return self.q.popleft()

    def top(self):
        if self.q:
            return self.q[0]

    def size(self):
        return len(self.q)


# ── Driver Code ────────────────────────────────────────
if __name__ == '__main__':
    s = Stack()
    s.push(10)
    s.push(20)
    s.push(30)
    print("Top:", s.top())          # 30
    s.pop()
    print("Top after pop:", s.top()) # 20
SECTION 05

C++ Implementation

C++ gives us std::queue from the <queue> header. We'll implement both methods. The logic mirrors the Python version but uses C++ syntax and templates for type generality.

METHOD 1 — Push-Heavy (O(n) Push, O(1) Pop)

C++ — Method 1: Push-Heavy 
// Stack Using Two Queues — Method 1 (Push-Heavy)
// Push: O(n)  |  Pop: O(1)  |  Top: O(1)

#include <iostream>
#include <queue>
using namespace std;

class Stack {
private:
    queue<int> q1;   // main queue  — holds stack in LIFO order
    queue<int> q2;   // auxiliary queue

public:
    // ── push ───────────────────────────────────────────
    void push(int x) {
        // Step 1: Enqueue new element into q2
        q2.push(x);

        // Step 2: Move all of q1 into q2
        while (!q1.empty()) {
            q2.push(q1.front());
            q1.pop();
        }

        // Step 3: Swap q1 and q2
        swap(q1, q2);
    }

    // ── pop ────────────────────────────────────────────
    void pop() {
        if (!q1.empty()) {
            q1.pop();   // O(1)
        }
    }

    // ── top ────────────────────────────────────────────
    int top() {
        if (!q1.empty()) {
            return q1.front();   // O(1)
        }
        return -1;   // sentinel for empty stack
    }

    // ── size ───────────────────────────────────────────
    int size() {
        return q1.size();
    }

    // ── isEmpty ────────────────────────────────────────
    bool isEmpty() {
        return q1.empty();
    }
};

// ── Driver Code ────────────────────────────────────────
int main() {
    Stack s;

    s.push(1);
    s.push(2);
    s.push(3);

    cout << "Current size: " << s.size() << endl;  // 3
    cout << "Top: "         << s.top()  << endl;  // 3

    s.pop();
    cout << "Top after pop: " << s.top() << endl;  // 2

    s.pop();
    cout << "Top after pop: " << s.top() << endl;  // 1

    cout << "Current size: " << s.size() << endl;  // 1
    cout << "Is empty? "    << s.isEmpty() << endl; // 0 (false)

    return 0;
}

METHOD 2 — Pop-Heavy (O(1) Push, O(n) Pop)

C++ — Method 2: Pop-Heavy 
// Stack Using Two Queues — Method 2 (Pop-Heavy)
// Push: O(1)  |  Pop: O(n)  |  Top: O(n)

#include <iostream>
#include <queue>
using namespace std;

class Stack {
private:
    queue<int> q1;
    queue<int> q2;

public:
    // ── push ───────────────────────────────────────────
    void push(int x) {
        q1.push(x);   // O(1) — just enqueue
    }

    // ── pop ────────────────────────────────────────────
    void pop() {
        if (q1.empty()) return;

        // Move all but last element into q2
        while (q1.size() != 1) {
            q2.push(q1.front());
            q1.pop();
        }

        // Discard the last element (stack top)
        q1.pop();

        // Swap: q2 is now the new q1
        swap(q1, q2);
    }

    // ── top ────────────────────────────────────────────
    int top() {
        if (q1.empty()) return -1;

        // Move all but last element to q2
        while (q1.size() != 1) {
            q2.push(q1.front());
            q1.pop();
        }

        // Save the top value
        int topVal = q1.front();

        // Move it to q2 too (peek only)
        q2.push(q1.front());
        q1.pop();

        // Swap back
        swap(q1, q2);

        return topVal;
    }

    int size() { return q1.size(); }
    bool isEmpty() { return q1.empty(); }
};

// ── Driver Code ────────────────────────────────────────
int main() {
    Stack s;

    s.push(1);
    s.push(2);
    s.push(3);

    cout << "Current size: " << s.size() << endl;  // 3
    cout << "Top: "         << s.top()  << endl;  // 3

    s.pop();
    cout << "Top after pop: " << s.top() << endl;  // 2

    s.pop();
    cout << "Top after pop: " << s.top() << endl;  // 1

    cout << "Current size: " << s.size() << endl;  // 1

    return 0;
}

BONUS — Single Queue in C++

C++ — Bonus: Single Queue Method 
// Stack Using a SINGLE Queue in C++

#include <iostream>
#include <queue>
using namespace std;

class Stack {
private:
    queue<int> q;

public:
    void push(int x) {
        q.push(x);
        // Rotate: move all earlier elements behind the new one
        int sz = q.size();
        for (int i = 0; i < sz - 1; i++) {
            q.push(q.front());
            q.pop();
        }
    }

    void pop() {
        if (!q.empty()) q.pop();
    }

    int top() {
        if (!q.empty()) return q.front();
        return -1;
    }

    int size() { return q.size(); }
    bool isEmpty() { return q.empty(); }
};

int main() {
    Stack s;
    s.push(10);
    s.push(20);
    s.push(30);
    cout << "Top: " << s.top() << endl;  // 30
    s.pop();
    cout << "Top: " << s.top() << endl;  // 20
    return 0;
}

⚡ KEY INSIGHT
You always pay a cost of O(n) somewhere — either on push or on pop. The space complexity is always O(n) for all methods, since we must store all elements. The native stack is always faster, so use this approach only when constrained to queue-based systems.

This is where it gets exciting! Stack-using-queue patterns are more relevant to game development than you might think. Here's where you'd encounter — and potentially use — this concept in a real game project.

🎮 WHY GAME DEVS CARE ABOUT THIS
Many game engines and frameworks expose only queue-based event or message systems. When you need LIFO (stack) behaviour inside them — for undo, state reversal, or recursive backtracking — you implement a stack using the available queue API. This is exactly what this technique is for.

1. Undo / Redo System

Every action a player takes — building a structure, placing a tile, firing an arrow — is pushed onto an undo stack. When they press Ctrl+Z, the top action is popped and reversed. If the underlying event bus only supports queues (common in ECS architectures), you simulate the undo stack using this technique.

Used in: city builders, puzzle games, level editors, RTS games.

Python — Undo System for a Game Using Stack-on-Queue 
from collections import deque

class UndoStack:
    """Stack implemented via queue — used inside a queue-based event system."""
    def __init__(self):
        self.q1 = deque()
        self.q2 = deque()

    def record_action(self, action):
        """Push action to undo stack (Method 1 — O(n) push, O(1) pop)."""
        self.q2.append(action)
        while self.q1:
            self.q2.append(self.q1.popleft())
        self.q1, self.q2 = self.q2, self.q1

    def undo(self):
        """Pop last action and reverse it — O(1)."""
        if self.q1:
            action = self.q1.popleft()
            action['reverse']()   # Call the reverse function
            return action
        print("Nothing to undo!")

    def last_action(self):
        if self.q1:
            return self.q1[0]


# ── Game Simulation ────────────────────────────────────
player_gold = 100
player_hp   = 200

def spend_gold(amount):
    global player_gold
    player_gold -= amount
    print(f"Spent {amount} gold. Remaining: {player_gold}")

def refund_gold(amount):
    global player_gold
    player_gold += amount
    print(f"Refunded {amount} gold. Remaining: {player_gold}")

undo_sys = UndoStack()

# Player buys a sword for 30 gold
spend_gold(30)
undo_sys.record_action({
    'name': 'buy_sword',
    'reverse': lambda: refund_gold(30)
})

# Player buys a shield for 50 gold
spend_gold(50)
undo_sys.record_action({
    'name': 'buy_shield',
    'reverse': lambda: refund_gold(50)
})

print("\n--- Player presses UNDO ---")
undo_sys.undo()   # Refunds shield — last action reversed first
undo_sys.undo()   # Refunds sword

2. Maze & Dungeon Pathfinding (DFS Backtracking)

Depth-First Search (DFS) — used to generate and solve mazes, find paths in dungeons, and explore game maps — uses a stack internally. If you're in an environment where only a queue interface is exposed (e.g., a custom async job system), you replicate the DFS stack using this pattern.

Used in: roguelikes, dungeon crawlers, maze games.

Python — DFS Dungeon Path Using Stack-on-Queue 
from collections import deque

class DFSStack:
    def __init__(self):
        self.q1 = deque()
        self.q2 = deque()

    def push(self, node):
        self.q2.append(node)
        while self.q1:
            self.q2.append(self.q1.popleft())
        self.q1, self.q2 = self.q2, self.q1

    def pop(self):
        if self.q1: return self.q1.popleft()

    def is_empty(self):
        return len(self.q1) == 0


def dfs_dungeon(graph, start, target):
    """DFS using our queue-based stack to find path in dungeon."""
    stack   = DFSStack()
    visited = set()
    path    = []

    stack.push((start, [start]))

    while not stack.is_empty():
        node, current_path = stack.pop()

        if node == target:
            print(f"Path found: {' → '.join(current_path)}")
            return current_path

        if node not in visited:
            visited.add(node)
            for neighbor in graph.get(node, []):
                if neighbor not in visited:
                    stack.push((neighbor, current_path + [neighbor]))

    print("No path found!")
    return []


# ── Dungeon Map (adjacency list) ───────────────────────
dungeon = {
    'Entrance': ['Hall A', 'Hall B'],
    'Hall A':   ['Trap Room', 'Armory'],
    'Hall B':   ['Boss Room'],
    'Trap Room':[],
    'Armory':   ['Boss Room'],
    'Boss Room':[],
}

dfs_dungeon(dungeon, 'Entrance', 'Boss Room')
# Output: Path found: Entrance → Hall A → Armory → Boss Room

3. Game State Machine (Scene / Screen Navigation)

Every game has states: Main Menu → Gameplay → Inventory → Pause Menu. Pushing and popping states on a stack lets you navigate backwards correctly (like pressing ESC). When the state manager is built on a message queue architecture, you implement the navigation stack this way.

Used in: RPGs, adventure games, mobile games.

4. Expression Evaluator for Scripted Game Events

Many games use scripted event formulas — damage calculations like (ATK * 2 + BONUS) * CRIT_MULTI. Evaluating these infix expressions requires a stack (the Shunting Yard algorithm). If your scripting engine only exposes a queue to the runtime, this pattern fills the gap.

Used in: RPG damage systems, strategy game formulas, card games.

5. Animation / Cutscene Sequence Manager

When a complex cutscene plays, animations are pushed to a stack: play forward on push, reverse on pop (for rewind or skip-back features). In engines that route animation commands through a FIFO event queue, the stack-on-queue approach preserves the correct LIFO playback order.

Used in: visual novels, cinematic RPGs, story-driven games.

SECTION 08

🌐 Real-World Applications

Beyond games, this concept shows up across software engineering wherever you must adapt interfaces or work within constrained system boundaries.

1. Browser History (Back Button)

Web browsers maintain navigation history as a stack — the back button pops the last-visited URL. In distributed browser implementations or cloud-based remote browsers, the history state may be communicated via message queues between processes. The receiving process reconstructs LIFO behaviour using a stack-on-queue.

2. Call Stack Simulation in Interpreters

When building a custom programming language interpreter or a scripting engine (like Lua embedded in a game engine), you simulate a call stack using whatever primitives the host system offers. If the host only exposes a FIFO queue (e.g., a WebAssembly linear memory queue), you build the call stack on top of it.

3. Transaction Rollback in Databases

Database systems maintain a redo log as a queue (operations appended in order). When a transaction needs to be rolled back, operations must be undone in reverse order — LIFO. Database engines internally simulate a stack over the queue to achieve this reverse traversal efficiently.

4. Compiler Parsing & Syntax Trees

Compilers use a stack during recursive descent parsing. In certain distributed compilation pipelines, parse events are dispatched via message queues (e.g., Apache Kafka). The parser worker reconstructs the parse stack from these queue messages using this exact data structure pattern.

5. Robotic Task Scheduling

Robots process a stream of task events via a message queue (FIFO). When a higher-priority interrupt occurs and the robot needs to resume its previous task upon completion, a stack-on-queue structure maintains the task history — the robot can "pop" back to what it was doing before the interrupt.

6. Version Control Systems (Git-like)

Git's commit history is conceptually a stack — the most recent commit is always on top. Internally, commits arrive through a replication queue in distributed git servers. The server reconstructs the LIFO commit order using a stack simulated on top of the incoming event queue.

7. Operating System Process Management

OS schedulers sometimes use priority queues that need to be reversed for certain preemptive scheduling algorithms. When a high-priority task interrupts, the interrupted tasks must be restored in LIFO order — the kernel uses a stack built on top of its existing queue infrastructure.

Summary & Key Takeaways

✅ WHAT YOU LEARNED
  • A Stack (LIFO) can be fully simulated using one or two Queues (FIFO).
  • Method 1 (Push-Heavy): O(n) push, O(1) pop/top — best when you read more than you write.
  • Method 2 (Pop-Heavy): O(1) push, O(n) pop/top — best when you write more than you read.
  • Single Queue: Rotate after each push. Cleaner implementation, same complexity as Method 1.
  • Space complexity is always O(n) — you can't escape storing n elements.
  • In game dev, the pattern powers undo systems, DFS pathfinding, state machines, and animation sequencers.
  • In the real world, it's used in compilers, databases, OS schedulers, distributed systems, and robotics.
