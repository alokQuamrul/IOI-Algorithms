01

WHAT IS A QUEUE?
THE REAL-WORLD CONCEPT

Imagine you are at the lunch line in a school cafeteria. The first person who joined the line gets their food first. New people join at the back of the line. Nobody cuts in front. That's a Queue.

Or think about it in game terms — in a multiplayer game lobby, the first player who clicked "Find Match" is the first one to be placed into a match. Players who click later wait behind them. The game processes them in order.

🎮 GAME ANALOGY

In a tower defense game, enemies appear one by one from a path entrance. The first enemy to spawn is the first one walking on the path. All enemies line up in a Queue — first in, first to attack your towers!

In computer science, a Queue is a linear data structure that follows the FIFO principle:

FIFO = First In, First Out

The element that was added first is always removed first. Think of it like a tube — things go in one end and come out the other end.

◀ FRONT (exit here) REAR (enter here) ▶
A[0]
→
B[1]
→
C[2]
→
D[3]
A was added first → A will leave first | D was added last → D leaves last

Here, A is at the FRONT — it was the first one added and will be the first to be removed. D is at the REAR — it was the last one added.

02

HOW A QUEUE WORKS
THE RULES

A queue has two ends and only two valid points of interaction:

  • REAR (Back End) — This is where new items are added. This operation is called Enqueue.
  • FRONT (Front End) — This is where items are removed. This operation is called Dequeue.
⚠ CRITICAL RULE

You can NEVER remove from the rear or add from the front. Violating this makes it no longer a proper Queue. It's like someone cutting into the middle of a game lobby line — against the rules!

Visualizing Enqueue and Dequeue

Let's trace through what happens step by step when we add and remove players from a game lobby queue.

Step 1: Queue starts empty:

—[0]
—[1]
—[2]
—[3]
Empty queue. No players yet.

Step 2: Enqueue "Player1", "Player2", "Player3":

◀ FRONT REAR ▶
P1[0]
→
P2[1]
→
P3[2]
—[3]
Three players in line. Player1 will be matched first.

Step 3: Dequeue — Player1 gets matched and leaves the front:

◀ FRONT REAR ▶
P2[0]
→
P3[1]
—[2]
—[3]
Player1 was matched! Player2 is now at the front.
03

SETTING UP OUR QUEUE
USING AN ARRAY (LIST)

In Python, we don't have a built-in "array" type by default, but we use lists instead. Python lists are dynamic arrays — they grow and shrink as needed, which makes them perfect for building a queue.

ℹ INFO

A Python list is basically an array. It stores items in order, with each item at a numbered index starting from 0. Think of it like a row of lockers in a game level — locker 0, locker 1, locker 2...

The Simplest Queue in Python

The most beginner-friendly approach is to use a Python list directly. Let's start here before we build a proper class:

PYTHON
# Creating an empty queue using a Python list
queue = []

# Enqueue (add to the rear) - we use append()
queue.append("Player1")
queue.append("Player2")
queue.append("Player3")

print(queue)   # ['Player1', 'Player2', 'Player3']

# Dequeue (remove from the front) - we use pop(0)
first_player = queue.pop(0)

print(first_player)  # Player1
print(queue)         # ['Player2', 'Player3']

Let's break this down line by line so everything makes sense:

  • queue = [] — Creates an empty list. This is our queue. It has nothing in it yet.
  • queue.append("Player1") — The append() method adds an item to the end (rear) of the list. This is our Enqueue operation.
  • queue.pop(0) — The pop(0) method removes and returns the item at index 0 (the front of our list). This is our Dequeue operation.
⚠ PERFORMANCE NOTE

Using pop(0) is simple but slow for very large queues because Python has to shift every remaining element one step forward. For now it's fine to learn with, but in Section 5 we'll improve this!

04

CORE OPERATIONS:
ENQUEUE, DEQUEUE, PEEK & MORE

A proper Queue supports several operations. Let's learn each one with code examples:

1. Enqueue — Adding to the Queue

Enqueue means adding a new item to the rear (back) of the queue. In Python with a list, we use append().

PYTHON
queue = []

# Enqueue operation
def enqueue(queue, item):
    queue.append(item)   # Add to the rear
    print(f"Added: {item} | Queue: {queue}")

enqueue(queue, "Sword")
enqueue(queue, "Shield")
enqueue(queue, "Potion")
OUTPUT
Added: Sword   | Queue: ['Sword']
Added: Shield  | Queue: ['Sword', 'Shield']
Added: Potion  | Queue: ['Sword', 'Shield', 'Potion']

2. Dequeue — Removing from the Queue

Dequeue means removing and returning the item at the front of the queue. We must first check if the queue is empty — you can't remove from an empty queue!

PYTHON
def dequeue(queue):
    if len(queue) == 0:     # Check if queue is empty
        print("Queue is empty! Nothing to remove.")
        return None
    
    item = queue.pop(0)   # Remove from the FRONT (index 0)
    print(f"Removed: {item} | Queue: {queue}")
    return item

# Using our queue from before: ['Sword', 'Shield', 'Potion']
dequeue(queue)   # Removes 'Sword' (first in, first out)
dequeue(queue)   # Removes 'Shield'
OUTPUT
Removed: Sword  | Queue: ['Shield', 'Potion']
Removed: Shield | Queue: ['Potion']

3. Peek (or Front) — Look Without Removing

Sometimes you want to see what's at the front of the queue without actually removing it. This is called Peek. Like looking at the first card in your hand without playing it.

PYTHON
def peek(queue):
    if len(queue) == 0:
        print("Queue is empty!")
        return None
    
    return queue[0]   # Just READ index 0, do NOT remove it

queue = ["Boss", "Minion", "Dragon"]
front_enemy = peek(queue)

print(f"Next enemy: {front_enemy}")
print(f"Queue unchanged: {queue}")
OUTPUT
Next enemy: Boss
Queue unchanged: ['Boss', 'Minion', 'Dragon']

4. is_empty — Check if Queue Has Items

Before dequeuing, we need to know if the queue is empty. This prevents errors in our program (and crashes in our game!).

PYTHON
def is_empty(queue):
    return len(queue) == 0   # Returns True if empty, False otherwise

empty_q = []
full_q = ["Item1", "Item2"]

print(is_empty(empty_q))   # True
print(is_empty(full_q))    # False
OUTPUT
True
False

5. size — How Many Items Are in the Queue?

PYTHON
def size(queue):
    return len(queue)   # len() gives us the number of items

queue = ["Level1", "Level2", "Level3"]
print(f"Levels in queue: {size(queue)}")   # 3
05

A COMPLETE QUEUE CLASS
PUTTING IT ALL TOGETHER

Instead of passing a list into separate functions every time, the professional way to handle a queue in Python is to wrap everything into a class. A class bundles the data (the list) and the operations (enqueue, dequeue, etc.) into one neat package — like a game object that knows how to manage itself.

ℹ WHAT IS A CLASS?

Think of a class as a blueprint. Just like a "Character" blueprint in a game defines what every character can do (move, attack, defend), a Queue class defines what every queue can do (enqueue, dequeue, peek...). You create an instance (an actual queue object) from that blueprint.

PYTHON — COMPLETE QUEUE CLASS
class Queue:
    """
    A Queue data structure implemented using a Python list.
    Follows FIFO: First In, First Out.
    """
    
    def __init__(self):
        # This runs when we create a new Queue object
        self.items = []   # Our internal list (the actual storage)
    
    def enqueue(self, item):
        # Add item to the REAR of the queue
        self.items.append(item)
    
    def dequeue(self):
        # Remove and return item from the FRONT of the queue
        if self.is_empty():
            raise IndexError("Dequeue from empty queue!")
        return self.items.pop(0)
    
    def peek(self):
        # Look at the FRONT item without removing it
        if self.is_empty():
            raise IndexError("Peek at empty queue!")
        return self.items[0]
    
    def is_empty(self):
        # Returns True if the queue has no items
        return len(self.items) == 0
    
    def size(self):
        # Returns how many items are in the queue
        return len(self.items)
    
    def display(self):
        # Print the queue nicely
        if self.is_empty():
            print("[ EMPTY QUEUE ]")
        else:
            print(f"FRONT → {self.items} ← REAR")
    
    def __str__(self):
        # Called when you print() the queue object directly
        return f"Queue({self.items})"

Using Our Queue Class

Now let's put the Queue class to use with a real game scenario — managing a sequence of enemies spawning into a level:

PYTHON — GAME EXAMPLE
# ---- ENEMY SPAWN QUEUE SIMULATION ----

enemy_spawn_queue = Queue()

# Adding enemies to the spawn queue
print("=== Queuing up enemies ===")
enemy_spawn_queue.enqueue("Goblin")
enemy_spawn_queue.enqueue("Orc")
enemy_spawn_queue.enqueue("Troll")
enemy_spawn_queue.enqueue("Dragon Boss")
enemy_spawn_queue.display()

print(f"\nTotal enemies queued: {enemy_spawn_queue.size()}")
print(f"Next to spawn: {enemy_spawn_queue.peek()}")

# Simulating spawning each enemy one by one
print("\n=== Spawning enemies ===")
while not enemy_spawn_queue.is_empty():
    enemy = enemy_spawn_queue.dequeue()
    print(f"SPAWNED: {enemy}!")
    enemy_spawn_queue.display()

print("\n=== All enemies have spawned! ===")
OUTPUT
===  Queuing up enemies ===
FRONT → ['Goblin', 'Orc', 'Troll', 'Dragon Boss'] ← REAR

Total enemies queued: 4
Next to spawn: Goblin

=== Spawning enemies ===
SPAWNED: Goblin!
FRONT → ['Orc', 'Troll', 'Dragon Boss'] ← REAR
SPAWNED: Orc!
FRONT → ['Troll', 'Dragon Boss'] ← REAR
SPAWNED: Troll!
FRONT → ['Dragon Boss'] ← REAR
SPAWNED: Dragon Boss!
[ EMPTY QUEUE ]

=== All enemies have spawned! ===
✔ TIP

Notice the while not enemy_spawn_queue.is_empty() loop — this is the classic pattern for processing a queue! Keep going until there's nothing left. You'll see this in real game engines too.

06

TYPES OF QUEUES

Now that you've mastered the basic queue, let's look at the different flavors that exist. Think of these as different game modes of the same game!

1. Simple Queue (Linear Queue)

This is what we've been building. Items go in at the rear and leave from the front. Simple and straightforward — like your tutorial zone.

2. Circular Queue

In a linear queue using an array, when items are dequeued from the front, that space goes to waste. A Circular Queue reuses those empty front spaces by wrapping around — like a circular track in a racing game.

PYTHON — CIRCULAR QUEUE (SIMPLIFIED)
class CircularQueue:
    def __init__(self, capacity):
        self.capacity = capacity
        self.items = [None] * capacity   # Fixed-size array
        self.front = -1
        self.rear = -1
        self.count = 0
    
    def is_full(self):
        return self.count == self.capacity
    
    def is_empty(self):
        return self.count == 0
    
    def enqueue(self, item):
        if self.is_full():
            print("Queue is full!")
            return
        # Wrap around using modulo (%) operator
        self.rear = (self.rear + 1) % self.capacity
        self.items[self.rear] = item
        if self.front == -1:   # First item
            self.front = 0
        self.count += 1
    
    def dequeue(self):
        if self.is_empty():
            print("Queue is empty!")
            return None
        item = self.items[self.front]
        self.items[self.front] = None
        self.front = (self.front + 1) % self.capacity
        self.count -= 1
        return item

# Example usage
cq = CircularQueue(4)
cq.enqueue("Bullet1")
cq.enqueue("Bullet2")
cq.enqueue("Bullet3")
print(cq.dequeue())   # Bullet1
cq.enqueue("Bullet4")   # Reuses the freed slot!
print(cq.items)         # [None, 'Bullet2', 'Bullet3', 'Bullet4'] or similar

3. Priority Queue

In a normal queue, everyone waits in the order they arrived. In a Priority Queue, items with higher priority are processed first — regardless of when they arrived. In a game, think of a "stun" effect interrupting the normal attack queue!

PYTHON — PRIORITY QUEUE CONCEPT
# Python has a built-in heap queue (priority queue)
import heapq

priority_queue = []

# Format: (priority_number, item)
# LOWER number = HIGHER priority (1 = most urgent)
heapq.heappush(priority_queue, (3, "Normal Attack"))
heapq.heappush(priority_queue, (1, "Critical Heal"))    # Most urgent!
heapq.heappush(priority_queue, (2, "Shield Buff"))

# Items come out in priority order, not insertion order
while priority_queue:
    priority, action = heapq.heappop(priority_queue)
    print(f"Priority {priority}: Executing '{action}'")
OUTPUT
Priority 1: Executing 'Critical Heal'
Priority 2: Executing 'Shield Buff'
Priority 3: Executing 'Normal Attack'

4. Deque (Double-Ended Queue)

A Deque (pronounced "deck") lets you add and remove from both ends. Python's collections.deque is perfect for this and is also much faster than using pop(0) on a list.

PYTHON — DEQUE
from collections import deque

# Better performance Queue using deque
fast_queue = deque()

fast_queue.append("Action1")         # Add to rear
fast_queue.append("Action2")
fast_queue.appendleft("UrgentAct")   # Add to FRONT (deque feature)

print(fast_queue)
# deque(['UrgentAct', 'Action1', 'Action2'])

fast_queue.popleft()   # Remove from front — this is O(1), very fast!
print(fast_queue)
# deque(['Action1', 'Action2'])
✔ PRO TIP

For real Python projects (and games!), use collections.deque instead of a plain list for your queue. popleft() is O(1) — extremely fast — compared to pop(0) on a list which is O(n) and slows down as the queue grows.

07

TIME & SPACE COMPLEXITY

As a game developer, you care about performance. Slow code means lag. Lag makes players quit. Let's understand how fast our queue operations are.

We use Big O notation to describe speed. Think of O(1) as "instant" — no matter how big the queue is, it takes the same time. O(n) means "it gets slower as the queue grows."

OPERATION LIST (pop(0)) DEQUE (popleft) NOTE
Enqueue (add) O(1) O(1) Both are fast
Dequeue (remove) O(n) O(1) Deque wins big here!
Peek (look) O(1) O(1) Both instant
is_empty O(1) O(1) Both instant
size O(1) O(1) Both instant
Space used O(n) — proportional to number of items More items = more memory
ℹ WHY IS pop(0) SLOW?

When you remove index 0 from a Python list, Python has to shift every remaining element one position to the left to fill the gap. If you have 10,000 enemies in a queue, that's 10,000 shift operations just to remove one! A deque avoids this by using a smarter internal structure.

QUEUES IN GAME DEVELOPMENT

This is the part you came here for. Let's explore all the places queues power real game mechanics — and write code for each one!

🗡 USE CASE 1: ENEMY WAVE SPAWNER

Tower defense, dungeon crawlers, and wave-based shooters need enemies to appear in a specific order. A queue is the perfect tool — fill it with enemy types before the wave starts, then dequeue one enemy at a time to spawn them.

PYTHON — ENEMY WAVE SPAWNER
from collections import deque

class WaveSpawner:
    def __init__(self):
        self.wave_queue = deque()
        self.wave_number = 0
    
    def load_wave(self, enemies):
        self.wave_number += 1
        for enemy in enemies:
            self.wave_queue.append(enemy)
        print(f"Wave {self.wave_number} loaded: {enemies}")
    
    def spawn_next(self):
        if not self.wave_queue:
            print("All enemies spawned! Wave complete.")
            return None
        enemy = self.wave_queue.popleft()
        print(f"  >> SPAWNING: {enemy}")
        return enemy

# Game simulation
spawner = WaveSpawner()
spawner.load_wave(["Goblin", "Goblin", "Orc", "Troll", "BOSS"])

print("\n--- Wave begins! ---")
for _ in range(6):   # Try to spawn 6 (only 5 exist)
    spawner.spawn_next()
OUTPUT
Wave 1 loaded: ['Goblin', 'Goblin', 'Orc', 'Troll', 'BOSS']

--- Wave begins! ---
  >> SPAWNING: Goblin
  >> SPAWNING: Goblin
  >> SPAWNING: Orc
  >> SPAWNING: Troll
  >> SPAWNING: BOSS
All enemies spawned! Wave complete.

🎮 USE CASE 2: PLAYER ACTION QUEUE (TURN-BASED GAMES)

In turn-based strategy games like chess or RPGs, players queue up their actions. The game processes them one by one in the order they were entered. This is exactly a queue in action.

PYTHON — TURN-BASED ACTION QUEUE
from collections import deque

class TurnBasedGame:
    def __init__(self):
        self.action_queue = deque()
        self.turn = 1
    
    def queue_action(self, player, action):
        self.action_queue.append({'player': player, 'action': action})
        print(f"[{player}] queued action: {action}")
    
    def process_turn(self):
        print(f"\n=== Processing Turn {self.turn} ===")
        while self.action_queue:
            action_data = self.action_queue.popleft()
            print(f"  ➤ {action_data['player']} executes: {action_data['action']}")
        self.turn += 1

game = TurnBasedGame()
game.queue_action("Hero", "Attack Goblin")
game.queue_action("Mage", "Cast Fireball")
game.queue_action("Healer", "Heal Hero")
game.process_turn()
OUTPUT
[Hero] queued action: Attack Goblin
[Mage] queued action: Cast Fireball
[Healer] queued action: Heal Hero

=== Processing Turn 1 ===
  ➤ Hero executes: Attack Goblin
  ➤ Mage executes: Cast Fireball
  ➤ Healer executes: Heal Hero

🔫 USE CASE 3: BULLET / PROJECTILE POOL

Games that need many bullets on screen at once pre-create them in a queue (an "object pool"). When a bullet is needed, dequeue one. When it's done, enqueue it back. This is much faster than creating/destroying objects constantly — a key optimization trick!

PYTHON — BULLET OBJECT POOL
from collections import deque

class BulletPool:
    def __init__(self, pool_size):
        # Pre-create all bullet objects at game start
        self.pool = deque([{'id': i, 'active': False}
                           for i in range(pool_size)])
        print(f"Bullet pool created with {pool_size} bullets.")
    
    def fire(self, x, y, direction):
        if not self.pool:
            print("No bullets available! Reload first.")
            return None
        bullet = self.pool.popleft()   # Get bullet from pool
        bullet['active'] = True
        bullet['x'] = x
        bullet['y'] = y
        bullet['dir'] = direction
        print(f"FIRED bullet #{bullet['id']} at ({x},{y}) going {direction}")
        return bullet
    
    def recycle(self, bullet):
        # When bullet hits something, return it to the pool
        bullet['active'] = False
        self.pool.append(bullet)
        print(f"Bullet #{bullet['id']} recycled back to pool.")

pool = BulletPool(3)

b1 = pool.fire(10, 20, "RIGHT")
b2 = pool.fire(15, 25, "UP")
pool.recycle(b1)     # b1 hits enemy and returns
b3 = pool.fire(5, 5, "LEFT")   # Reuses b1's slot!

💬 USE CASE 4: DIALOGUE / CUTSCENE QUEUE

RPGs have characters speak lines one after another. These lines are stored in a queue. The game presses "Next" → dequeue the next line → display it. No complex logic needed, just FIFO ordering.

PYTHON — DIALOGUE SYSTEM
from collections import deque

class DialogueSystem:
    def __init__(self):
        self.dialogue_queue = deque()
    
    def load_scene(self, lines):
        for character, text in lines:
            self.dialogue_queue.append((character, text))
    
    def next_line(self):
        # Called when player presses [A] or clicks "Next"
        if not self.dialogue_queue:
            print("[Scene ended]")
            return
        character, text = self.dialogue_queue.popleft()
        print(f"  {character}: \"{text}\"")

dlg = DialogueSystem()
dlg.load_scene([
    ("Hero",   "Who are you?!"),
    ("Villain", "I am your final challenge."),
    ("Hero",   "Then prepare to fall!"),
    ("Villain", "Ha! You amuse me."),
])

print("--- Cutscene Start ---")
while dlg.dialogue_queue:
    dlg.next_line()
dlg.next_line()   # One extra call to show end
OUTPUT
--- Cutscene Start ---
  Hero: "Who are you?!"
  Villain: "I am your final challenge."
  Hero: "Then prepare to fall!"
  Villain: "Ha! You amuse me."
[Scene ended]

↩ USE CASE 5: UNDO SYSTEM (DEQUE AS HISTORY)

Many strategy and puzzle games let you undo moves. Every action is pushed to a queue/deque. When you undo, you pop the latest action and reverse it. This is a classic deque use case in games.

PYTHON — UNDO SYSTEM
from collections import deque

class GameWithUndo:
    def __init__(self):
        self.history = deque(maxlen=10)   # Keep last 10 actions max
        self.position = [0, 0]
    
    def move(self, direction):
        old_pos = self.position.copy()
        if direction == "right":   self.position[0] += 1
        elif direction == "up":   self.position[1] += 1
        self.history.append(('move', old_pos))
        print(f"Moved {direction} → Position: {self.position}")
    
    def undo(self):
        if not self.history:
            print("Nothing to undo!")
            return
        action, old_pos = self.history.pop()   # pop from RIGHT (latest)
        self.position = old_pos
        print(f"Undone! Back to: {self.position}")

g = GameWithUndo()
g.move("right")
g.move("right")
g.move("up")
g.undo()
g.undo()
OUTPUT
Moved right → Position: [1, 0]
Moved right → Position: [2, 0]
Moved up    → Position: [2, 1]
Undone! Back to: [2, 0]
Undone! Back to: [1, 0]

COMMON MISTAKES
& HOW TO AVOID THEM

Mistake 1 — Dequeuing from an Empty Queue

If you call pop(0) on an empty list, Python throws an IndexError and your game crashes! Always check before dequeuing.

PYTHON — WRONG VS RIGHT
# ❌ WRONG — will crash!
queue = []
item = queue.pop(0)   # IndexError: pop from empty list

# ✅ RIGHT — always check first
queue = []
if queue:   # Python treats empty list as False
    item = queue.pop(0)
else:
    print("Queue is empty, nothing to dequeue.")

Mistake 2 — Removing from the Wrong End

Remember: remove from the front (index 0), not the rear. pop() without an argument removes the last item — that's a stack behavior, not a queue!

PYTHON — WRONG VS RIGHT
# ❌ WRONG — this is Stack behavior (LIFO), not Queue!
queue = ["First", "Second", "Third"]
item = queue.pop()       # Removes "Third" (the LAST item) — WRONG for queue!

# ✅ RIGHT — Queue removes from FRONT
queue = ["First", "Second", "Third"]
item = queue.pop(0)     # Removes "First" — correct FIFO behavior

Mistake 3 — Forgetting That Lists are Slow for Dequeue

For game queues that process many items per second, using pop(0) on a large list is a performance killer. Use collections.deque in real projects.

PYTHON — PERFORMANCE COMPARISON
import time
from collections import deque

N = 50000

# List approach
list_q = list(range(N))
start = time.time()
while list_q: list_q.pop(0)
print(f"List (pop 0): {time.time() - start:.4f} seconds")

# Deque approach
deq_q = deque(range(N))
start = time.time()
while deq_q: deq_q.popleft()
print(f"Deque popleft: {time.time() - start:.4f} seconds")

# Deque is typically 100-200x faster!
