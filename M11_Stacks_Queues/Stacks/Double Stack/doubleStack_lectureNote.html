Lecture Notes: Double Stack in Python

1. Stack – A Quick Refresher (For Beginners)

A stack is like a stack of plates: you can only add or remove the top plate.

This is called LIFO (Last In, First Out).

Basic stack operations:

  • push(item) – add an item to the top
  • pop() – remove and return the top item
  • peek() / top() – look at the top item without removing it
  • is_empty() – check if the stack has no items

In Python, we can use a list as a stack:

stack = []
stack.append(5) # push
top = stack.pop() # pop

Now let's move to double stack.

2. What is a Double Stack?

Double stack simply means two stacks.

They can be used independently – for example, one stack for player actions, another for enemy actions in a game.

There are two common ways to implement two stacks:

Approach Description
Brute Force Two separate lists (each stack gets its own list)
Optimized (Space efficient) One single array that holds both stacks – one grows from left, the other from right

We will study both approaches.

3. Brute Force Approach – Two Separate Stacks

This is the simplest way: create two independent Python lists.

class DoubleStackBruteForce:
    def __init__(self):
        self.stack1 = [] # first stack
        self.stack2 = [] # second stack

    # Operations for stack1
    def push1(self, item):
        self.stack1.append(item)

    def pop1(self):
        if not self.stack1:
            raise IndexError("Stack1 is empty")
        return self.stack1.pop()

    # Operations for stack2
    def push2(self, item):
        self.stack2.append(item)

    def pop2(self):
        if not self.stack2:
            raise IndexError("Stack2 is empty")
        return self.stack2.pop()

    def is_empty1(self):
        return len(self.stack1) == 0

    def is_empty2(self):
        return len(self.stack2) == 0

✅ Advantages:

  • Very easy to understand and code
  • Each stack can grow as large as available memory

❌ Disadvantages (why "brute force"?):

  • Wastes memory if you know the total maximum size.
    For example, if you need 1000 elements total for both stacks, you might allocate 1000 for each list – that's 2000 slots, but only 1000 are used.
  • Two separate Python objects (two lists) also have some overhead.

For small games this is perfectly fine, but in memory-limited environments (like embedded devices or older consoles) we want an optimized version.

4. Optimized Approach – Two Stacks in One Array

We use a single list (array) of fixed size.

  • Stack 1 starts at index 0 and grows to the right.
  • Stack 2 starts at index n-1 and grows to the left.
  • When the two tops cross, the array is full.

[Diagram: left stack grows →, right stack grows ←]

4.1 How it works

  • top1 = index of the top element of stack1 (starts at -1)
  • top2 = index of the top element of stack2 (starts at size)
  • push1: increment top1 and place item there
  • push2: decrement top2 and place item there
  • Overflow happens when top1 + 1 == top2 (no empty slots left)

4.2 Python Implementation

class DoubleStackOptimized:
    def __init__(self, capacity):
        self.capacity = capacity # total size of the single array
        self.arr = [None] * capacity # one array holding both stacks
        self.top1 = -1 # stack1 starts empty from left
        self.top2 = capacity # stack2 starts empty from right

    # ----- Stack 1 (left side) -----
    def push1(self, item):
        if self.top1 + 1 == self.top2:
            raise OverflowError("Double stack is full")
        self.top1 += 1
        self.arr[self.top1] = item

    def pop1(self):
        if self.top1 == -1:
            raise IndexError("Stack1 is empty")
        item = self.arr[self.top1]
        self.arr[self.top1] = None # optional: clear reference
        self.top1 -= 1
        return item

    def peek1(self):
        if self.top1 == -1:
            return None
        return self.arr[self.top1]

    def is_empty1(self):
        return self.top1 == -1

    # ----- Stack 2 (right side) -----
    def push2(self, item):
        if self.top1 + 1 == self.top2:
            raise OverflowError("Double stack is full")
        self.top2 -= 1
        self.arr[self.top2] = item

    def pop2(self):
        if self.top2 == self.capacity:
            raise IndexError("Stack2 is empty")
        item = self.arr[self.top2]
        self.arr[self.top2] = None
        self.top2 += 1
        return item

    def peek2(self):
        if self.top2 == self.capacity:
            return None
        return self.arr[self.top2]

    def is_empty2(self):
        return self.top2 == self.capacity

4.3 Example usage

ds = DoubleStackOptimized(6)
ds.push1("A")
ds.push1("B")
ds.push2("Z")
ds.push2("Y")
print(ds.pop1()) # B
print(ds.pop2()) # Y
print(ds.peek1()) # A

4.4 Complexity Analysis

  • Time complexity: All operations are O(1) – push/pop are constant time.
  • Space complexity: O(capacity) – we use exactly one array of fixed size. No extra lists.

✅ Advantages of optimized approach:

  • No wasted slots – the total used space = sum of both stacks.
  • Memory efficient – ideal when you know maximum total elements.
  • Cache-friendly because both stacks live in the same contiguous memory.

❌ Disadvantages:

  • Fixed total capacity – cannot grow beyond the initial array size.
  • Slightly more complex logic (handling two tops).

5. Where Are Stacks Useful for Game Development?

As a game developer, you will use stacks all the time. Here are specific examples with code sketches.

🎮 Use Case 1: Undo / Redo System (Two Stacks!)

This is a perfect real‑world double stack:

  • Undo stack: stores previous states (player positions, inventory, etc.)
  • Redo stack: stores states that were undone, so the player can revert the undo.
class UndoRedo:
    def __init__(self):
        self.undo_stack = [] # history of actions
        self.redo_stack = [] # actions that were undone

    def do_action(self, action):
        # perform the action (e.g., move player)
        self.undo_stack.append(action)
        # clearing redo because a new action invalidates redo history
        self.redo_stack.clear()

    def undo(self):
        if not self.undo_stack:
            return
        action = self.undo_stack.pop()
        self.redo_stack.append(action)
        # revert the action (reverse movement, etc.)

    def redo(self):
        if not self.redo_stack:
            return
        action = self.redo_stack.pop()
        self.undo_stack.append(action)
        # re-apply the action

🎮 Use Case 2: Game State History (Save / Load)

When the player saves the game, you push the current state onto a stack.

Then you can implement a "rewind" feature.

game_states = [] # stack of saved states
game_states.append(current_state) # save
previous_state = game_states.pop() # load last save

🎮 Use Case 3: AI – Depth‑First Search (DFS)

Many pathfinding and puzzle‑solving algorithms use a stack.

For example, a monster that explores a maze:

def dfs_search(maze, start, goal):
    stack = [start]
    visited = set()
    while stack:
        pos = stack.pop()

🎮 Use Case 4: Inventory (Last Used Item)

In a game where the player can pick up items and use the most recently acquired first (like a stack of potions):

potion_stack = []
potion_stack.append("Health Potion")
potion_stack.append("Mana Potion")
last = potion_stack.pop() # uses Mana Potion first

🎮 Use Case 5: Dialogue System (Backtracking)

When a player makes dialogue choices, you can push each choice onto a stack, allowing a "back" button to return to previous dialogue lines.

🎮 Use Case 6: Level Navigation (Backtrack)

In a platformer, you can record the player's path. Pressing "rewind" pops positions from the stack and restores them.

6. Which Approach Should You Choose for Your Game?

Situation Recommendation
You are making a small game (2D platformer, puzzle) and you don't care about a few extra bytes. Brute force – two separate lists. It's easier to debug.
You are making a game for an embedded device (Game Boy, Arduino) or a memory‑intensive open world. Optimized – one array with two tops.
You need undo/redo. Use two independent stacks (the brute‑force pattern) – one for undo, one for redo.
You need three or more stacks. The optimized approach can be extended to multiple stacks, but becomes complex. Usually separate lists are fine.

7. Summary & Key Takeaways

  • Double stack = two stacks.
  • Brute force = two separate lists. Simple, but may waste memory.
  • Optimized = one array with two tops growing toward each other. Saves memory, fixed capacity.
  • Stacks are essential for games: undo/redo, AI pathfinding, inventories, dialogue, and more.
